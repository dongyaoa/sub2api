# 中国大陆网页访问限制与部署

后台「系统设置 → 安全设置」可以开启「禁止中国大陆 IP 访问网页」。默认关闭。
开启后，命中本地中国大陆 IPv4/IPv6 网段的访客会看到独立提示页。
首页、登录注册、用户页面、管理页面和 SPA 深链接均适用。

## 范围

- 仅限制网页访问。所有现有 API、SSE、WebSocket、支付服务器回调、OAuth
  服务器回调、健康检查仍由原有路由处理，不增加地区鉴权。
- 浏览器回跳到网站页面时，仍需通过网页地区判断。
- 静态 JS/CSS/图片资源保持可用。API 继续开放意味着这不是对后端数据的
  全面地理封锁；既有 API 身份验证、权限和配额继续生效。
- 仅命中中国大陆网段时拒绝。默认对不明、无效、本地/内网地址放行；显式
  本地网络模式下的环回请求改为检查本机公网出口。香港、澳门、
  台湾没有单独拦截规则。判定基于请求出口 IP，受数据准确性影响。

## 管理设置

- `web_access_cn_block_enabled`：总开关，默认 `false`。
- `web_access_block_message`：禁止页纯文本说明，最多 500 字符。
- `web_access_ip_allowlist`：网页豁免 IP/CIDR 列表，支持 IPv4、IPv6。
  白名单只豁免地区限制，登录和管理员权限检查仍正常执行。

可在后台预览提示页，预览不改变开关或当前访客的访问判定。
受限页同时显示中英文说明，不提供手动检查按钮；浏览器标题为
`Exclusively for overseas users`。后台样式预览不会修改管理页标题。
如果管理员也从中国大陆访问，开启前应配置管理 IP 白名单。
不要用整个公网范围作为管理员白名单。

## 真实 IP 和反向代理

网页地区判断固定使用 Gin 的 `server.trusted_proxies` 可信代理链。
它不读取浏览器提交的国家代码，不直接信任 `CF-IPCountry`，也不使用旧版
API Key 原始转发头兼容开关，避免改变 API 原有的 IP 解析行为。

反向代理需覆盖访客伪造的转发头，`server.trusted_proxies` 只填写实际直接
连接后端的代理 IP/CIDR。例如同机 Nginx 可配置 `127.0.0.1/32` 和 `::1/128`。
多级代理需按实际链路配置，并限制源站入口。配置缺失可能使所有访客都被
识别成代理的内网 IP，导致地区限制无法生效。

独立静态前端部署必须把 `/api/v1/settings/web-access` 转发到后端。
Vite 本地开发已有 `/api` 代理。浏览器访问 `127.0.0.1` 或 `localhost` 时，
HTTP 请求只携带环回地址，无法直接反映所处地区。可以明确设置
`WEB_ACCESS_LOCAL_NETWORK_CHECK=true`，且后端必须仅监听环回地址。此时只有
环回访客会通过固定 HTTPS 服务查询本机公网出口，再使用相同的离线网段库判断。
项目本地启动脚本已启用这一模式；这是实际网络查询，不是固定模拟为中国大陆。

该模式默认关闭，非环回监听、远程访客、普通内网地址均不使用本机出口替代
访客 IP。线上反向代理部署必须保留默认关闭，并正确配置可信代理链。
本机出口受实际路由和代理配置影响，不是对人的物理位置的判断。代理选择规则：

- 显式设置的 `HTTP_PROXY` / `HTTPS_PROXY`（含小写形式）优先，并遵守
  `NO_PROXY` / `no_proxy` 的直连例外。
- 未显式设置上述代理变量时，Windows 跟随当前用户的手动系统代理，仍遵守
  `NO_PROXY`；非 Windows 不读取系统代理。系统代理的 PAC/自动发现模式不受
  支持，配置读取或解析失败时返回可重试的不可用状态，不静默改为直连。

这些规则只用于本地网页地区检查，不修改系统代理或现有 API 上游连接。
关闭网页开关时不查询公网；开启时出口查询成功和失败均缓存 5 秒。
检测失败显示可重试的不可用页面，不把失败当作境外或静默放行。
查询不附带用户凭据、浏览器请求头或访客数据；固定回显服务会看到这次连接的公网来源。

## 缓存与生效

`GET /api/v1/settings/web-access` 返回当前访客的结果，使用
`Cache-Control: private, no-store`。访客结果不写入共享公开设置或 HTML 缓存。
开启限制时，嵌入式网页 HTML 也不允许共享缓存；判断在 HTML 缓存及 304
处理之前执行。CDN 不应强制缓存网页 HTML 或这个访问状态接口。

配置保存后本实例缓存立即失效；其他实例在配置缓存有效期结束后同步。
前端从原有公共设置或 HTML 注入的 `__APP_CONFIG__` 读取有效开关。
开关关闭时沿用正常页面流程，不请求地区状态接口，不启动地区轮询、聚焦或
路由检测；后端也不解析访客地区、不读取本地代理或查询公网出口。原有站点
公共配置加载仍正常执行，公开配置只包含开关，不包含访客地区或白名单。

开启后，已打开的 Vue 页面在导航、重新聚焦时复检；线上 `client_ip` 模式每 60 秒自动
复检，服务端确认 `local_network` 后改为每 5 秒，退出本地模式时恢复 60 秒。
受限后卸载正常界面。这些周期不根据浏览器 hostname 推断。确认关闭后停止
所有地区检查，并忽略关闭前尚未完成的检测结果。已处于关闭状态的其它标签页
在刷新页面或原有公共配置更新后感知重新开启，不通过额外轮询监测开关。

本地切换系统代理配置后，下一次查询会重读配置并使旧出口结果失效；同一代理
地址内切换节点时，正常情况下需等待最多约 5 秒出口缓存及下一次复检，另加
网络查询耗时。直接返回的 HTTP 403 静态页不自动轮询，刷新页面即可发起新的
判断。线上仍按真实访客 IP 判定，所有 API 调用不受影响。

后台复检遇到短暂网络错误时保留最后已确认的状态并重试，避免丢失未保存表单；
已明确受限的页面不会因网络错误而放行。首次检查失败则显示可重试页面。
明确启用的本地出口检测如果失败，服务端返回专门的不可用原因；即使之前
处于允许状态，也会显示可重试页面，不把检测失败当作允许访问。
服务端配置读取故障返回可重试的暂不可用页面，不把读取失败当作关闭开关；
这不影响现有 API 路由。

## 应急恢复

若管理 IP 变化导致无法进入后台，在后端进程环境中设置
`WEB_ACCESS_FORCE_DISABLED=true` 并重启后端，可以临时关闭网页地区限制。
随后登录后台修正白名单或关闭开关，移除应急环境变量并再次重启。
该变量不修改持久化设置，不关闭登录验证或 API 安全控制。

本地查看效果也可能限制管理员页面。若需恢复管理，在停止当前本地后端后，
可以使用 `.dev/start-local.ps1 -DisableWebAccess` 启动临时关闭地区限制的实例。
修正设置后恢复普通启动方式；不要将这个应急参数用于正式开启限制的运行实例。

## 地区数据更新

线上按访客 IP 离线查询，不向外部服务发送访客 IP。显式本地网络模式仅为
取得本机出口访问固定回显服务，之后仍使用离线网段库。数据来源、MIT 许可证及固定版本
记录在 `backend/internal/service/geoipdata/README.md`。更新两份数据后需重新
构建后端；建议随正常发布检查更新。网段资料并非实时物理位置证明，发现
误判应核实数据来源并更新，必要时暂时关闭网页限制。
