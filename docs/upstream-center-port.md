鹈鹕每个计划保留最近 20 条终态记录，活动记录另行展示。用户和管理员复用同一份历史。开启用户展示仅改变可见性，不会开启定时任务或发出模型请求。账号监控弹窗的读取也不触发模型请求；通过账号入口新接入的状态监控默认关闭。

添加或编辑上游 Key 分组时，已有账号候选由服务端按该上游网址及显式配置的 API 地址筛选，再搜索和分页，不依赖上游是否已有分组。按协议、域名和端口确定站点，忽略 `/v1` 等路径及默认端口差异；不同子域、非默认端口不会混入。候选接口只返回账号标识、名称、协议和 API 地址，不返回 Key 或用量数据；未配置有效网址时返回空列表。

Key 分组绑定现有 API Key 账号后，可用性检测、模型获取、消费余额与倍率同步（包括强制同步）动态继承账号管理中的当前出口代理；使用该分组的智商监控（鹈鹕与糖果）同样继承。已建立的绑定无需重新添加分组。HTTP / HTTPS / SOCKS5H 代理负责上游域名解析，代理地址可以是管理员配置的本地出口服务。请求仍检查上游 URL、拒绝私网字面地址及已知元数据主机，并禁止重定向转发密钥。没有代理配置的账号使用原直连方式；配置代理但不可用时明确报错，不自动改走直连。

每次执行核对绑定账号的协议、地址和 API Key，代理信息仅在服务端本次请求中使用，不复制到分组或作品记录。账号更换代理后下一次执行自动使用新配置；代理池按账号现有可用节点选择规则运行。一个 Key 分组绑定多个账号时，代理配置须一致，否则提示冲突。引用已有分组的独立监控继承来源绑定，来源归档、失效或凭据变化时不再借用旧代理。智商任务还会核对入队时的地址与 Key，避免把旧任务凭据发送到变化后的来源；本站分组与 OAuth 继续使用它们原有的账号调度路线。

监控中心添加监控时，可选择已有上游 Key 分组，自动填入地址与协议，由服务端读取分组 Key；检测模型、间隔和启停独立设置。New API 监控持续复用来源分组的站点授权，站点授权更新或清除时同步生效，不需要重复填写令牌。独立监控不绑定业务账号、不重复导入收入；手工修改地址、协议、Key 或取消复用后解除来源，可自行配置。卡片显示对应平台图标和最近 45 次记录，按可用宽度排列；完整检测历史仍按存储保留策略保存。

## 财务口径

所有上游只统计当天账目：利润 = 本站今日用户消费 - 上游 API Key 今日实际消费。Sub2API 上游通过 `/v1/usage` 获取今日数据，传入 `days=1`、`timezone=<本站时区>`，`start_date` / `end_date` 均为今日，成本直接使用 `usage.today.actual_cost`。已移除近 30 天远端读取、汇总计算、快照字段读写和前端模块，不再扫描历史费用。日期筛选由上游完成，今日口径遵循上游返回值。

Sub2API 今日请求单次最多等待 20 秒、含重试总预算 26 秒，所有请求仍受整轮 45 秒预算及 60 秒同步租约约束。瞬时连接错误、超时和部分网关错误最多重试一次；授权错误、证书错误、限流及不支持的接口不盲目重试。页面区分超时、DNS、连接、TLS 和 HTTP 状态，不返回原始凭据或错误详情。请求跨午夜时不把无法确认日期的旧消费标成今日。

从账号管理导入并绑定 API Key 时，将该账号当天保留的真实使用记录加入后台补齐任务；保存请求不扫描历史。后台每批按本站今日零点限制读取范围，旧版本遗留任务也只补当天，已经过期或游标已越过今日的任务直接结束。处理进度持久保存，多个服务实例不会重复计账。补齐期间保留已同步收入、暂不计算利润；完成后统计自动接续。收入使用 `usage_logs.actual_cost`，请求数和 Token 同步归集。按使用记录唯一标识去重，不覆盖已归属其他上游的账目；更换绑定和恢复归档继续遵守原绑定区间，归档期间不回填。旧日志没有每次请求的 API Key 指纹，因此导入按账号管理的记录口径，账号曾更换 Key 的记录无法进一步拆分；已清理且未记入独立账本的记录无法补回。仅复制凭据到独立监控不会导入业务收入。

New API 仅同步当天上游消费，停止近 30 天的远端日志读取。`/api/usage/token/` 只提供 Key 累计额度，今日消费从实际使用日志汇总，并按本站时区划分日期。仅有模型 Key 时读取 `/api/log/token`，只要求确认覆盖完整今日，缺少历史记录不影响今日结果。记录不足时，在添加或编辑上游时开启站点级「消费、余额与倍率授权」，填写用户 ID 和控制台个人访问令牌；同站点的 Key 分组共享授权，添加分组不再重复填写。服务端校验 Key 归属后，分页读取 `/api/log/self` 中今日零点至本轮截止时间的记录，按准确的 `token_id` 分别统计多个 Key，不使用可重名的 Key 名称、累计额度或整个账号消费代替。

站点授权默认采用上游网站地址，也可设置 API 地址（含部署路径前缀）。仅规范化后协议、主机和路径前缀一致的分组继承授权，修改站点身份需重新提供令牌；独立监控仍可单独配置。升级时，同一站点、同一用户的旧分组授权自动提升为站点授权，存在多个用户或地址冲突则保留旧配置并提示在编辑上游时统一设置。修改或清除站点授权会同步更新其分组并使旧费用快照失效；同站点同用户的钱包只展示一次，Key 消费仍分别统计。

New API 原始消费先按 `/api/status` 返回的 `quota_per_unit` 转成 USD 额度，再应用可选充值比例；缺少额度单位时不猜测金额。同一账号的今日日志读取共享缓存，成功缓存与失败续读等待均为 30 秒；日志较多时分批跨同步轮次续读，完成后才发布金额。超过单次分页上限或发现上游计数封顶时，按不重叠的秒级时间窗口拆分，完成各窗口核验后汇总；中途限流或超时保留进度。大扫描完成时如果截止时间已经落后，本轮剩余预算内再追一轮增量，不再等候旧缓存过期。单秒内数据仍超出可验证范围时保留待同步状态。成功后的今日刷新补读新增日志，并定期完整校准，始终保留真实截止时间，不把部分日志总和作为完整消费。

已配置站点授权的 New API 目标每轮完成后约 30 秒再次同步；仅有模型 Key 的目标仍遵守站点级两次请求 / 130 秒的预算，多 Key 按等待顺序轮流获取，避免单个分组持续占用额度。实际更新时间取决于上游响应、限流及完整记录量。分组与账目统一只展示今日消费和利润。

New API Key 分组在「智商监控」旁提供「强制同步」，调用管理员接口 `POST /api/v1/admin/upstream-center/targets/:id/force-sync`。该操作立即推进今日消费，跳过已完成消费缓存的有效期和重试等待，保留可续读进度、在途请求共享及站点限流，不触发模型检测或历史消费读取。响应以 `usage_sync_status` 区分今日消费已同步、仍在推进及失败；钱包更新成功不会误报为消费已同步。

钱包余额正常时，钱包卡片不再重复展示消费日志尚未同步完整的警告，消费与利润区域继续标识实际的待同步或旧数据状态。余额读取失败、授权错误和金额单位未知仍显示对应提示。USD 金额统一显示 `$`，去掉中文浏览器可能生成的 `US$` 前缀，其他币种及 QUOTA 额度单位保留。

全站与供应商汇总仅包含当前未归档、且当天有本站业务调用的 Key。参与范围依据业务账本记录，零收入请求也算业务调用；仅有上游可用性检测记录的 Key 不参与总成本和总利润，也不会使总计等待同步。全部 Key 都未使用时，汇总收入、成本和利润为零。显式选择单个 Key 时仍可查看其今日实际消费，方便核对监控及站外用量。

归档不会清空其他 Key 的统计，历史账本保留，恢复后重新纳入；修改供应商归属前的收入不会混入新的供应商。有本站业务调用的 Key 若缺少实际消费，显示其余参与 Key 的已知消费和缺失数量，待数据完整后再计算利润，不把缺失消费按零计算。

供应商支持可选的充值比例 `recharge_ratio`：实付 1 单位可获得 N 单位上游额度，实际成本 = 上游额度消费 ÷ N。例如设置 1:10，上游消费 100、本站用户消费 15，实际成本为 10、利润为 5。未设置时沿用原金额，页面仅对已设置的站点显示比例和换算说明；原始消费快照不修改。此设置是额度成本换算，不自动查询货币汇率；调整比例会按新比例重算今日展示。

顶部总统计始终显示金额：总利润 = 当前今日用户消费合计 − 已同步的今日上游消费合计。延迟或失败的 Key 沿用当天最近一次成功消费；尚未取得或无法核对的成本暂不计入，并在利润卡片中标注数量或缺失状态，数据补齐后自动重算。全部成本缺失时已计入成本合计为 0，这表示合计尚未取得数据，不表示各 Key 实际消费为零。使用服务端已去重、已换算充值比例的总额，不累加分组利润；本站收入补齐中也保留提示。该规则只用于顶部总计，单上游及 Key 明细继续按完整性判断利润。

本站有新请求不会清空上游消费；同日同步暂时失败或消费数据超过 3 分钟未更新时，保留最近成功获取的实际金额并显示同步时间及旧数据提示。单上游及 Key 明细利润仍等待有效数据，顶部总利润继续按已同步合计展示。单纯钱包刷新不会把刚同步的今日消费判为过期。跨日不会把昨日快照作为今日消费，也不会用账号倍率估算成本。

本地账本的 `account_stats_cost × account_rate_multiplier` 是本站账号计费统计，不是上游实扣，不能作为成本或利润依据。页面不再展示无法匹配的逐笔上游成本与利润，也不再请求逐笔账目接口。Key 级上游消费可能包含站外调用及监控用量；同一汇总范围内相同上游地址和 Key 的实际消费只计一次，汇总利润也不等同于本站独占的现金利润。

`GET /api/v1/admin/upstream-center/finance/summary` 只聚合本站时区当天，直接返回今日 `UpstreamFinanceSummary`，不再返回 `today` / `last_30_days` 包装对象；前后端需要同时更新。旧迁移和历史数据库列保留用于升级兼容，运行时代码不再读取或写入近 30 天快照，不清空已有历史账本。

管理员从「上游中心 → 站内监控 → 用户展示」开启用户入口并选择计划。用户接口挂在现有 JWT 鉴权路由下，继续执行分组访问权限校验。上游 Key 分组、独立监控和智商监控外部地址支持明确的 HTTP / HTTPS、公网域名或 IP、端口（1–65535）和路径前缀，例如 `http://216.158.77.26:7070/v1`；IPv6 使用 `[地址]:端口`。模型获取、余额、消费及倍率同步沿用所配置的协议和端口。New API 授权按协议、主机、端口和 API 路径范围匹配，HTTP 默认 80 与 HTTPS 默认 443 分别归一化；更换协议或端口仍需重新提供凭据。私网、回环和云元数据地址继续受保存及连接时校验约束；本站分组仍使用带一次性内部许可的回环请求。

上游管理采用默认展开的上游目录，与卡片并排布局，沿用原有筛选和排序。顶部「总设置」统一控制是否显示目录和桌面端左侧或右侧位置，修改立即生效并保存在当前浏览器；目录内不再提供设置按钮。隐藏目录时恢复显示全部上游，卡片自动占满可用区域。滚动页面时目录保持可见，上游较多时列表内部滚动。小屏改为横向滚动目录，避免挤压卡片。切换后定位到结果区域；右下角保留回到顶部按钮，移动端展开主菜单时隐藏该按钮。

上游目录桌面宽度为 172px。监控开启时，「上次更新」显示具体秒数；暂停时显示刚刚、分钟、小时或天，悬停仍可查看完整时间。开启与暂停的记录条分别共用秒级、分钟级时钟，暂停卡片不随秒级时钟刷新；页面隐藏时暂停计时、最后一个组件卸载时清理，启停切换及新检测时间会立即更新显示。

新增 Key 分组及可用性监控默认每 60 秒检测一次；OpenAI 默认模型为 `gpt-6.1-sol`，Anthropic 为 `claude-sonnet-5`，Gemini 沿用 `gemini-2.5-flash`。手动新增、已有账号导入、账号管理接入与后端默认值保持一致；已有分组及手动选择的模型、间隔保持原配置，智商与糖果测试的默认间隔独立设置。

用户端每组前 8 个终态作品在可见时自动加载播放，后续作品仅鼠标悬停或键盘聚焦时加载播放；尚未访问的作品不预先请求 HTML 或建立 iframe，也不提前测量作品布局。移出视野、鼠标离开按需预览或页面隐藏时暂停动画，并取消未完成加载；已加载作品复用缓存和预览。打开详情时优先加载所选作品，复用其正在进行的请求，并暂停背景动画；倒计时不再导致整组作品每秒重新渲染。原有 iframe 沙箱、内容安全策略及作品访问权限继续生效。

站内监控支持可选的鹈鹕提示词：每个监控可填写自己的提示词，选择本站分组后还可获取该分组的上游渠道（账号）并逐个覆盖。执行优先级为「实际调用渠道的提示词 → 该监控的提示词 → 默认鹈鹕提示词」，留空即可继承；提示词应要求输出 HTML 或 SVG 动画，以便继续使用作品预览。渠道调度与重试沿用原逻辑，每次转发按照实际选中的渠道应用提示词。配置在任务入队时保存快照，作品历史记录实际使用的提示词，之后修改配置不改变旧作品；糖果测试继续使用固定题目。

智商监控的上游 Key 和外部地址来源同样支持可选鹈鹕提示词，留空恢复默认，作品记录保留实际提示词；按渠道覆盖仅用于本站分组，OAuth 来源沿用默认提示词。糖果结果条只显示成功取得有效答案的记录，答对 21 显示绿色，判为错答才显示红色；请求失败和空答案不占结果条，错误详情仍可查看。Key 分组名前以淡绿色 OpenAI、淡橙色 Anthropic、淡蓝色 Gemini 标识协议。

`GET /api/v1/admin/intelligence-monitors/local-channels?group_id=<ID>` 仅向管理员返回分组内渠道的基本名称与状态，不返回凭据。保存时校验渠道属于选中的分组；更换分组后需重新配置渠道提示词。单个提示词最多 8000 个字符，最多设置 200 个渠道，全部提示词合计最多 64000 个字符。新增迁移 `268_intelligence_monitor_prompts.sql` 为原计划补充空配置，原监控继续使用默认提示词。

「存储管理 → 归档数据 → 恢复」调用 `POST /api/v1/admin/upstream-center/storage/restore`，请求为 `{kind,id}`，支持 `supplier`、`target` 和 `intelligence`。上游恢复只包含与其同批归档的 Key，先前单独归档的 Key 仍留在归档列表。原账号绑定若仍有效且未被其他 Key 占用，则从恢复时刻建立新的绑定区间，不回填归档期间消费；绑定冲突时整个恢复操作回滚并提示。

恢复后的监控保持暂停，保留原有作品记录和历史账本，不自动发出付费检测。智商监控归档时已经清除的外部密钥、删除的专用站内密钥或失效来源，需要恢复后重新配置；页面会提示。永久清理或已按保留策略清除的记录不在可恢复范围内。

归档上游或 Key 分组时，关联智商监控一起归档；恢复时同时恢复同批归档的计划和作品，并保持暂停。永久删除则清除关联计划、全部作品和糖果记录、检测历史、余额与倍率快照、上游独立账本与成本汇总、绑定及历史补齐任务、公开展示中的计划引用。源账号、借用的站内密钥与真实站内用户消费记录不随之删除。

「数据管理 → 已归档项目 → 一键删除全部归档」需输入确认词，调用 `POST /api/v1/admin/upstream-center/storage/purge-archives`。首次请求 `{}`，后续传 `{cursor}`；每批处理最多 25 个归档根项目（包含关联数据），前端自动续批，覆盖超过 200 条的归档。运行中项目跳过并显示数量；执行期间新增或恢复的归档不纳入原清理范围。清理只删除数据库中的对应数据，PostgreSQL 可复用释放空间，但不保证文件立即缩小，不自动运行会长时间锁表的 `VACUUM FULL`。

## 部署配置

默认鹈鹕并发为 8、糖果并发为 4，可在配置文件中设置：

```yaml
intelligence_monitor:
  max_concurrency: 8
  candy_max_concurrency: 4
```

也可使用环境变量 `INTELLIGENCE_MONITOR_MAX_CONCURRENCY`（1–256）和 `INTELLIGENCE_MONITOR_CANDY_MAX_CONCURRENCY`（1–128）。同数据库的多个实例共享并发上限，部署默认值应一致；部署配置变更需要重启。在上游中心「并发设置」保存后的数据库值优先，在线调整立即生效，调小不会终止已发出的请求。

计划默认使用 `gpt-6-astra`、`high`，可选择 `gpt-6.1-sol`；新建计划默认每 5 分钟执行，单次最多等待 10 分钟，可选择 5 / 10 / 15 分钟超时。可用性检测与鹈鹕 / 糖果是各自独立的任务。

后端使用现有加密器保存凭据，沿用现有数据库和密钥配置。后台定时执行不依赖浏览器打开。本站分组和 OAuth 的长生成请求保留工作任务的总时限，单独使用响应头等待预算，避免污染普通请求的连接池配置；正常业务计费继续使用独立计费上下文。

## 人工验收路径

1. 管理员进入上游中心，确认五个 Tab、并发设置和存储管理可用；创建厂家并导入已有 API Key 账号，核对分组、绑定、排序、编辑与归档。
2. 配置一条可用性监控，检查手动检测、定时启停、模型切换、状态历史、余额和倍率同步；上游今日实际消费 1 元、同账期站内用户消费 2 元时，核对今日利润为 1 元；再核对负利润、同步失败和未知值状态。
3. 在账号管理打开 API Key 和 OAuth 账号的「监控」，核对与上游中心共用目标 / 计划，打开弹窗不会自行产生检测；验证暂停、编辑和历史作品同步。
4. 创建站内分组计划，通过有访问权限的正常密钥执行；核对实际执行来源、生成超时、鹈鹕和糖果独立调度及作品保留。
5. 开启用户展示并选择站内计划，分别用有 / 无该分组权限的普通用户检查列表及作品详情；撤销展示后直接详情访问也应失效。
6. 在测试数据上删除单幅终态作品、OAuth 计划和 OAuth 账号，确认关联记录及时消失且正在执行的旧任务不能重新写回。

真实模型生成、OAuth 额度状态、第三方余额与最终费用需要使用部署环境内已授权的线路验收；自动化测试覆盖本地逻辑、模拟上游和数据库行为。核对仅当天汇总、同日失败保留金额、跨日旧快照不复用，以及页面不再展示近 30 天统计或逐笔明细；检查站外调用与监控用量已包含在 Key 级上游消费中，共享 Key 不重复计费。直接上游 / 外部 / OAuth 智商生成未单独计入厂家账本，不能把今日汇总利润当作扣除了全部生成费用的现金利润。
