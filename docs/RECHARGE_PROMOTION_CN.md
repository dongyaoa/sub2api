# 阶梯充值加赠

先在 **系统设置 → 功能开关 → 活动中心** 打开总开关并保存，再从管理员左侧栏进入 **活动中心**。

活动中心提供三个页签：**数据概览**、**充值赠送明细**、**活动配置**。在配置页设置活动并点击“保存活动”。首次打开提供默认关闭的通用示例，不会自动发布；默认日期为明天北京时间零点起，持续七天。

关闭系统总开关后，左侧入口、活动页面及用户充值活动展示隐藏，新充值不再加赠，统计及活动配置写入接口同时关闭。已有配置和账务记录保留；已创建订单继续按下单时的快照履约。再次启用可复用已有配置。

## 规则

- 同一时间维护一份活动配置，可修改名称、寄语、起止时间、支付币种、1–10 个档位和单笔赠送上限，以后节日继续复用。
- 表单时间统一按北京时间解释。开始时间包含在活动内，结束时间不包含；关闭或到期后用户页面自动收起活动展示。
- 每笔符合条件的余额充值自动参与，取满足门槛的最高一档，不累计各档位。订阅订单不参与。
- 门槛使用所选支付通道的币种，且不包含手续费；币种不匹配的订单不享受加赠。
- 基础额度 = 充值金额 × 普通充值倍率，四舍五入到两位小数；赠送额度 = 基础额度 × 赠送百分比，再四舍五入到两位小数。
- 单笔赠送上限使用 **站内美元额度**，0 表示不限制。最终到账是基础额度与赠送额度之和，现金实付及手续费保持正常充值规则。
- 本版不提供总预算、总名额或每人次数限制，单笔上限不能替代全站预算。

例如，普通充值倍率为 0.15，CNY 充值满 100 加赠 10%：充值 100 元时基础额度为 $15，赠送 $1.50，合计到账 $16.50；支付手续费另按原设置计算。

## 展示与账务

充值表单使用紧凑的香槟金渐变提示和档位按钮，余额卡下方有小活动提示；用户仪表盘顶部提供活动充值入口，侧栏充值入口附带金色“活动 / BONUS”标记。所有展示仅在总开关、支付/余额充值可用且活动正在有效期内时出现，结束后自动隐藏。侧栏和仪表盘共享活动配置缓存，充值页复用原有结算信息。

活动中心采用独立页签、统计卡、赠金收支环形图、活动排期进度和明细表；配置页提供规则预览及到账试算。试算使用站点充值倍率，不修改配置，也不代表活动已启用。支持中英文、深色模式和手机布局。

数据概览显示已到账订单、去重参与人数、基础额度、已发放赠金、退回赠金及净赠金。现金实付包含手续费，按币种分别统计。明细支持北京时间日期范围、订单状态、用户/邮箱/订单号搜索及分页，可以查看下单时的活动快照。

日期范围按订单创建时间筛选，统计这批订单当前的到账及退款结果，不是现金流水发生期间的财务报表。待支付订单不计入已发放额度；只有退款成功的终态计入已退回额度。关闭、修改活动不会重置历史统计，可用日期筛选历次活动数据。

订单创建时将活动条款与基础/赠送额度保存在 `payment_orders.promotion_snapshot`。活动后续修改、关闭或结束，不改变已有订单的承诺。余额通过原支付履约路径一次入账，重复支付通知不重复赠送。订单详情和支付结果显示历史快照。

邀请返佣、累计充值及签到充值资格按基础额度统计，排除活动赠送。赠送额度进入现有余额，没有独立到期时间。

## 退款

活动订单仅支持管理员审核整单退款，并必须扣回全部基础额度和赠送额度。余额不足不能强制退款，异步退款等待期间已扣额度保持不可用；渠道明确退款失败后恢复额度。网络超时、空响应或未知退款状态均进入待确认，保留已扣额度，禁止再次提交退款，避免“现金已退但余额被恢复”。支持查询的渠道可查询退款结果；渠道不支持查询或缺少退款编号时，需要管理员在渠道后台核对后人工处理。

已实际产生邀请返佣，或存在未解决的退款回滚失败记录的活动订单，暂不支持在线退款，需要线下核对处理。本版没有新增返佣冲正系统。普通非活动订单保持原退款规则。

## 安全边界

- 订单类型只接受明确的余额充值或订阅，拒绝用未知类型绕过充值倍率、禁用开关。
- 本金与赠金由服务端计算，使用下单快照和现有签名/实付金额/币种校验；重复支付通知仍由幂等履约处理。
- 内部支付兑换码只允许受信任的支付履约入口使用，普通用户兑换和管理员普通兑换不能将其兑换。
- 保存充值倍率时保留精度，拒绝入账金额为零或溢出的订单。
- 退款回收本金及赠金，结果不明时不恢复余额，重复通知和旧退款查询不能覆盖新处理结果。

现有 API 计费允许请求完成后再结算，管理员退款前仍需核对在途请求和未结算消费；本功能没有改成预扣余额计费。每笔充值均可参与、可分单、无总预算/每人上限是当前运营规则，单笔赠送上限不能代替全站成本控制。

## 部署

随正常版本发布执行迁移 `241_payment_order_promotion_snapshot.sql`，为支付订单添加可空活动快照及查询索引。旧订单没有活动快照，保持原有行为。活动配置存储在现有 settings 的 `RECHARGE_PROMOTION`，不新增活动表或钱包表。

系统总开关存储为 `recharge_promotion_enabled`，默认关闭。发布后开启功能，先保存活动自身为禁用状态的配置，核对时间、币种、倍率和档位，再启用活动。不要直接修改历史订单的活动快照。
